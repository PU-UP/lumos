## 实际入口与实现

`AGENTS.md` 为 Agent 入口，`docs/local-core.md` 为操作说明。Python 3.12+，标准库，无依赖安装。`lumos.py` 提供 init/status/context/verify、begin/commit/recover/abandon；`lumos_transfer.py` 通过同一命令入口提供 backup/restore 与 migrate-start/finish/cancel。

SQLite 保存脉络、依据、决定、行动、文档登记、当前关联及批次历史；Markdown 和原件有不可变正式版本与可编辑副本。保存保护覆盖读取基线、独立候选、正式事务及副本刷新。纠正需要明确影响核对，过时当前关联可在同批次撤下并指向新记录，旧关系仍保留在历史中。

迁移以本地持久状态和显式单主接管控制工具写入；普通恢复默认只读，sandbox 只用于隔离验证，trial 仅为迁移试运行。取消保留新根全量内容为非权威归档，不把试运行变化静默导入旧根。

## 可复现的运行验收

在工程根运行：

```text
py -3 -m unittest discover -s tests -v
py -3 lumos.py status
py -3 lumos.py context 入职
py -3 lumos.py verify
git check-ignore -v lumos-data/work/preparation.md lumos-data/control.json .local/acceptance/unittest.txt backups/local-core-20260923/manifest.json
git ls-files lumos-data .local backups
```

自动测试在新的隔离目录中运行，不改真实根。最终运行 19 项测试，全部通过，20.352 秒；完整输出保留 `.local/acceptance/unittest.txt`。故障注入仅是测试函数传入的 hook；其中保存各边界、迁移切换边界还以子进程 `os._exit` 验证进程消失后的恢复，不是仅同一调用栈重试。生产 CLI 没有故障注入开关。

## 不继承旧聊天的接续验收

使用独立子 Agent `cold_continuation`，以 `fork_turns=none` 启动；只提供 AGENTS、本地使用说明、两个数据根和接续请求，不提供原聊天或预期答案，禁止读取 fixture 构造代码和设计文档。

实际完成：

1. 只读真实根，正确区分已有准备背景与尚不存在的生产选择、技术试验或行动；没有把历史时间估计当当前剩余时间。
2. 从隔离持久数据解释旧理解为何被更正、当前阶段选择、行动阻塞条件，以及交流完成与技术验收的区别，给出能够继续讨论的下一步。
3. 用 begin→独立候选→commit→context 保存明确标为 Agent 建议的新理解，未虚构用户决定，批次 `8a49c4fe72bb4940b26d70457b2adb7d`，seq 从 2 到 3，读回通过。
4. 初次发现 incoming 尚不存在，以及当前边仍指向旧决定。已修正初始化／恢复创建 incoming，并补上同批次撤下旧关联及保存关系历史的最小操作。
5. 同一独立 Agent 只重读工具说明及隔离持久数据，完成纯关系修正批次 `f24b1772c0f04bb9afaedd9d3a1005ff`；读回 seq=4，当前边改指新决定，旧决定和原事实保留，link_changes 准确记录撤下／新增及原因，歧义已解决。incoming 的新建／恢复来自主 Agent 的实现和本地测试，独立 Agent 沿用现有目录，未声称亲自重测该项。

详细原始命令、自然接续回答、失败尝试和保存结果在 `.local/acceptance/cold-agent-report.md`，不将包含工作摘录的全文提交 Git。复现时使用新的隔离目录：


让无旧聊天的新 Agent 仅按 AGENTS 和本地工具读取该根，回答“继续建图定位的问题；我忘了上次为什么改方向”，再保存一条不冒充用户决定的建议并读回。该样例标为隔离模拟，不可用于真实根初始化。

这证明在这些记录上能冷启动并继续保存；不证明已经经历一个月间隔或持续真实技术工作。真实的第二条技术脉络与后续工作体验仍需在实际讨论中验证。
