# 四角色可靠性修复与复核

2026-11-22。范围为 Windows 本机单用户体验版，不迁移正式记录。

## 修复内容

- 后台循环遇到数据库锁、数据解析或其他执行异常时保留异常日志，健康接口明确报告暂停和最近检查时间；线程已经退出时报告停止，不能沿用此前的可用状态。下一轮继续检查，不主动重试已失败的业务作业。各工作页、对话和答复入口显示暂停/停止状态，原输入保留。
- 角色模型偏好保存到数据根 `role-models.json`，按角色校验并检测并发修改，纳入既有备份恢复。浏览器仅导入服务端尚未设置的偏好；默认模型的空值保留。首次领取任务固定完整角色模型，内部决定使用 Lumos 的模型，专业处理使用对应角色的模型，失败重试不被后续偏好更改影响。回执记录实际选择；旧回执不补造型号。笔记自动整理的显式 Astra 规则保留。
- Ops 获得同一对话的原话及答复，仍不接收无关任务正文、未答业务问题、Lumos 回报或业务提案。对话历史不扩大权限。

## 回归与复核范围

覆盖数据库锁和意外异常后的恢复、死亡线程状态、模型接口写入防护、旧浏览器偏好导入、并发选择拒绝、明确选择默认、页面刷新与跨页同步、角色决定及重试模型快照、历史回执、Ops 续聊和资料边界、设置备份及只读恢复。

整体复核重新沿输入保存、领取、专业提案、Lumos 决定、整批保存、故障回报、消息已读、笔记原稿保护、资料固定版本和迁移恢复路径检查。判断边界是单用户本机，不把单元测试通过等同于长期实际使用验收。

浏览器已核对角色工作页与聊天框的模型一致、刷新后保留、Lumos/AIPM 设置互不覆盖，截图 `.local/role-reliability-models.jpg`。两轮真实 Ops 模型调用使用独立模拟库，第二轮准确复述第一轮代号 `OPS-91827`，两轮均使用服务端选择的 `gpt-6.2-sol`，未产生业务目标更新；结果 `.local/role-reliability-live-ops.json`。模型并发刷新与选择交错时也必须按用户实际看到的旧值检查冲突，不能用刚刷新的值绕过冲突检查。

检查结果：后端全量运行 175 项；其中旧健康接口测试因新增 worker 字段而断言失败，更新预期后完整重跑该 HTTP 安全用例通过，其余 174 项通过。前端最终 199 项全量通过，`git diff --check` 通过。日志为 `.local/role-reliability-python.log`、`.local/role-reliability-python-recheck.log`、`.local/role-reliability-node.log`。正式库只读核对仍为 schema 1、seq 4248，未创建正式模型配置文件。浏览器日志另有未定位来源的 MutationObserver 报错；仓库前端没有使用此 API，未将其归因于业务代码或宣称浏览器日志全清零。

本轮三项缺陷已闭环，未发现新增的业务保存或角色越权问题。此结论不覆盖正式迁移、长期连续运行、实体手机或完整多角色真实模型业务验收；最新全库恢复演练仍待最终候选版执行。
