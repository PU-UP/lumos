# 网页笔记与 Agent 整理

入口：本机服务启动后打开 `/notes`，或从看板点击“笔记”。笔记属于工作空间，不要求先建脉络或任务。同日可多篇，按上海记录日期倒序展示，日期可补记，标题可留空（显示“未命名笔记”）。

## 写作与保存

标题和正文直接输入，停止输入约900毫秒自动保存，也可点击“保存当前内容”。自动保存更新当前内容，不新增用户可见历史版本。点击“结束记录”会先保存最新内容，再生成一个历史版本并进入阅读模式；下次打开默认阅读，点击“编辑”才重新允许修改。记录中离开再打开仍可继续编辑。已有笔记默认阅读，旧历史全部保留。支持轻量Markdown阅读：小标题、列表和HTTP(S)链接；原始HTML按文字显示，不执行脚本。正文上限20万字符，标题300字符。尚无附件、富文本块、云同步或离线网页。

每篇笔记独立递增revision，其他任务更新不阻塞笔记保存。同篇旧版本拒绝覆盖；界面同时保留草稿和最新版本，用户合并后显式保存。保存期间继续输入会在上一请求完成后另行保存。请求结果不明时先以相同request_id和内容重试，不能给重试换ID。

未保存内容在当前浏览器本地保留恢复草稿，以正式数据位置标识、标签页及笔记ID隔离；恢复后需点击保存。草稿不是另一份正式数据，也不进入服务器备份；清除浏览器存储会丢失尚未正式保存的草稿。存储不可用时页面会提示。关闭或跳转前有未保存内容时请求浏览器拦截离开，浏览器可能不支持拦截，因此仍需查看保存状态。

正式笔记是SQLite中独立note记录；每次“结束记录”形成一个可见历史版本；自动保存、开始编辑、归档与恢复仅保留内部审计修订，用于冲突检测、幂等恢复和固定来源引用，不进入新的用户历史列表。已有历史不删除。内部revision不是历史版本计数；任务已引用的任何修订仍不可变。笔记保存，沿用原子批次、会话保护、只读/迁移保护及完整备份恢复。无需人工编辑work文件。持久文档编辑会话期间拒绝保存，草稿保留，结束会话后刷新并重试。新笔记数据应使用本版本及其备份内配套引擎读取，旧引擎不认识note类型。

## 读取与归档

```text
py -3 lumos.py notes
py -3 lumos.py notes --workspace lumos --query 会议
py -3 lumos.py notes --archived
py -3 lumos.py note <笔记ID>
py -3 lumos.py note <笔记ID> --revision 2
py -3 lumos.py note-save <请求JSON>
```

`notes`默认灵光空间且只列未归档笔记，搜索标题和正文，结果包含摘要字段与revision；正文通过`note`显式读取。`--archived`只列归档。普通context不会沿关系自动载入笔记正文。任务详情只返回明确引用的版本及摘录，不扫描笔记库。

归档表示笔记内容已使用或纳入任务／项目，且本次无剩余待处理内容。先结束记录，再填写处理结果或资料去向后归档。归档后默认阅读，须恢复至未处理后才能编辑。归档可恢复，不代表任务完成，也不删除原文。人工归档填写原因；Agent根据用户要求或已授权整理规则归档，必须记录来源和原因。Agent每次完成笔记整理后必须主动检查归档：核对全文要点已有结论、任务或项目背景承接，保存并读回确切来源后，无剩余未整理内容就主动归档，不再逐篇请求确认。业务任务未完成或存在已转入任务跟踪的待定问题，不阻止笔记归档；仅讨论过、仅提取一项任务不等于整篇已处理。有遗漏、歧义或无明确去处的内容则保留未归档，并说明尚待处理项。归档原因写明处理结果与确切任务/项目去向，不能仅写“已讨论”。用户明确要求归档时按其指示执行，保留原文和固定版本引用，不改变关联任务状态。没有后台模型轮询或定时归档。

## Agent 保存与提炼任务

note-save请求示意（仅格式，不是真实工作记录）：

```json
{
  "request_id": "32位uuid十六进制",
  "id": "note-32位uuid十六进制",
  "expected_revision": 0,
  "changes": {"title": "标题", "body": "原文", "date": "2026-10-26", "workspace": "lingguang"},
  "source": {"type": "user", "ref": "可追溯的用户输入"}
}
```

请求顶层operation为save（默认，自动保存当前内容）、finish（结束记录并生成历史版本）、edit（重新开始编辑）。finish/edit的changes可为空。已结束笔记改正文前先edit；归档前先finish。旧历史按旧格式保留，不批量迁移。首次expected_revision为0；更新先读取note，用当前revision。changes只含改动字段，可改title/body/date/workspace/status/archive_reason。归档status为archived且archive_reason必填；恢复为active。Agent整理操作使用source.type=agent并说明用户授权及整理依据。网页写入来源由服务端固定为用户操作，不能伪造Agent来源。note返回历史与关联任务。

提炼任务先读取当前tasks，核对已有任务以避免重复；区分原话、转述、假设和已决定事项，不把笔记里的复选框自动当任务。不要无依据补日期或承诺。使用task-save的顶层note_refs关联来源，changes可为空以仅关联笔记。例：

```json
"note_refs": [{"id": "note-...", "revision": 2, "excerpt": "该版本正文中的确切摘录"}]
```

note_refs为完整列表替换，省略保留；更新先读取任务以保留其他来源。每个笔记版本至多一条引用，摘录必须是对应版本正文的连续原文；多个要点可选择包含它们的原文段落。固定引用版本，后续笔记修改和归档不会改掉既有依据。任务详情显示摘录并可打开引用版本（只读），笔记显示关联任务。新结论需另行更新任务进展或项目背景，不自动改旧引用。

长期项目背景仍走已有脉络与正式文档流程；记录明确笔记ID、版本和摘录来源，必要时把笔记引用附到任务。笔记本身始终保留，整理不覆盖原话。

## 验收

隔离数据覆盖：同日多篇/日期排序/空间与搜索、版本冲突、原请求重放、来源引用固定、归档恢复、只读与会话保护、HTTP来源和令牌检查、大段中文、备份及配套引擎恢复读取。前端覆盖保存中继续输入、失败重试、显式合并、安全阅读和归档恢复。实际浏览器验收结果在维护记录中保存；故障及样例均不进入真实工作数据。
