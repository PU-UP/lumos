# 网页笔记与 Agent 整理

2026-11-19流程：自动整理只固定原稿并通读全文后按主题重写、去重、理顺表达和格式；遇到疑问简短搜索官方资料，明确区分原话与资料补充，附日期和链接，未解问题列在正文最下方，可关联已有任务和主线；不修改业务记录，也不归档。点击“Lumos 归档”才由Codex Astra（gpt-6.2-astra）理解全文，保存知识依据、主线进展或任务状态，并归档。原稿与润色版均可从历史查看，失败保留原文并可重试。旧笔记不批量自动处理。

2026-11-21补充：全文已由现有来源承接时，Atlas 可通过 intake-apply 的 source_refs（id、连续原话 excerpt）固定已有来源的指纹与本轮引用，不必重复新增依据。归档回执直接显示承接来源；确有关键问题时，归档原因包含对应待答回执。背景未知继续保留，不因归档虚构结果、安排或重复提问。

入口：本机服务启动后打开 `/notes`，或从看板点击“笔记”。笔记属于工作空间，不要求先建脉络或任务。同日可多篇，按上海记录日期倒序展示，日期可补记，标题可留空（显示“未命名笔记”）。

## 写作与保存

标题和正文直接输入，停止输入约900毫秒自动保存，也可点击“保存当前内容”。自动保存更新当前内容，不新增用户可见历史版本。点击“自动整理”会先保存最新内容，再生成一个历史版本并进入阅读模式；下次打开默认阅读，点击“编辑”读取最新整理后的当前正文并允许继续修改，实际改动后按钮恢复“自动整理”。记录中离开再打开仍可继续编辑。已有笔记默认阅读，旧历史全部保留。格式栏支持小标题、次级标题、加粗、斜体、数字/字母/无序列表；回车自动续号，空项回车退出，Ctrl/Cmd+B/I设置强调。使用轻量Markdown保存和阅读，支持HTTP(S)链接；原始HTML按文字显示，不执行脚本。正文上限20万字符，标题300字符。尚无附件、富文本块、云同步或离线网页。

每篇笔记独立递增revision，其他任务更新不阻塞笔记保存。同篇旧版本拒绝覆盖；界面同时保留草稿和最新版本，用户合并后显式保存。保存期间继续输入会在上一请求完成后另行保存。请求结果不明时先以相同request_id和内容重试，不能给重试换ID。

未保存内容在当前浏览器本地保留恢复草稿，以正式数据位置标识、标签页及笔记ID隔离；恢复后需点击保存。草稿不是另一份正式数据，也不进入服务器备份；清除浏览器存储会丢失尚未正式保存的草稿。存储不可用时页面会提示。关闭或跳转前有未保存内容时请求浏览器拦截离开，浏览器可能不支持拦截，因此仍需查看保存状态。

正式笔记是SQLite中独立note记录；每次“自动整理”形成一个可见历史版本；自动保存、开始编辑、归档与恢复仅保留内部审计修订，用于冲突检测、幂等恢复和固定来源引用，不进入新的用户历史列表。已有历史不删除。内部revision不是历史版本计数；任务已引用的任何修订仍不可变。笔记保存，沿用原子批次、会话保护、只读/迁移保护及完整备份恢复。无需人工编辑work文件。持久文档编辑会话期间拒绝保存，草稿保留，结束会话后刷新并重试。新笔记数据应使用本版本及其备份内配套引擎读取，旧引擎不认识note类型。

## 读取与归档

```text
py -3 lumos.py notes
py -3 lumos.py notes --workspace lumos --query 会议
py -3 lumos.py notes --archived
py -3 lumos.py note <笔记ID>
py -3 lumos.py note <笔记ID> --revision 2
py -3 lumos.py note-save <请求JSON>
```

`notes`默认灵光空间且只列未归档笔记，搜索标题和正文，结果包含摘要字段与revision；正文通过`note`显式读取。`--archived`只列归档。普通context不会沿关系自动载入笔记正文。任务详情只返回明确引用的版本及摘录，不扫描笔记库。

“Lumos 归档”用于需要接续工作的笔记，须先自动整理并等待润色完成。业务更新和归档同批保存；需后续确认的问题保留在主线，不等同任务完成。失败不归档。

“手动归档”用于不重要、无需Agent阅读或处理的笔记：点击后弹窗确认，可直接从编辑状态归档，不触发润色或业务整理，并取消尚未完成的整理。已经自动整理而启动过的润色不能撤回已发送的内容，但迟到结果不再应用。普通归档无需填写处理去向，系统记录确认原因。

“删除”也须弹窗确认：从笔记列表移除，取消未完成整理，不删除已经被任务引用的固定版本与审计历史。已删除笔记不能编辑或自动整理，旧引用仍可读取。删除不是安全擦除历史。

归档可恢复。归档后的编辑、保存与自动整理保留归档状态，不重新自动入队；需重新处理时先恢复至未处理。历史笔记及既有来源不批量改写。

## Agent 保存与提炼任务

note-save请求示意（仅格式，不是真实工作记录）：

```json
{
  "request_id": "32位uuid十六进制",
  "id": "note-32位uuid十六进制",
  "expected_revision": 0,
  "changes": {"title": "标题", "body": "原文", "date": "2026-10-26", "workspace": "lingguang"},
  "source": {"type": "user", "ref": "可追溯的用户输入"}
}
```

请求顶层operation为save（默认，自动保存当前内容）、finish（自动整理并生成历史版本）、edit（重新开始编辑）。finish/edit的changes可为空。新增process（Lumos归档，changes为空）、archive（普通归档）、delete（删除）；archive/delete必须同时传confirmed=true。process要求active、finished、当前正文有成功的formatted_revision且没有未完成的笔记整理；正文/标题/日期/空间实际改动撤下此标记，重新整理成功后恢复。已结束笔记改正文前先edit。旧历史按旧格式保留，不批量迁移。首次expected_revision为0；更新先读取note，用当前revision。changes只含改动字段，可改title/body/date/workspace/status/archive_reason。归档status为archived且archive_reason必填；恢复为active。Agent整理操作使用source.type=agent并说明用户授权及整理依据。网页写入来源由服务端固定为用户操作，不能伪造Agent来源。note返回历史与关联任务。

提炼任务先读取当前tasks，核对已有任务以避免重复；区分原话、转述、假设和已决定事项，不把笔记里的复选框自动当任务。不要无依据补日期或承诺。使用task-save的顶层note_refs关联来源，changes可为空以仅关联笔记。例：

```json
"note_refs": [{"id": "note-...", "revision": 2, "excerpt": "该版本正文中的确切摘录"}]
```

note_refs为完整列表替换，省略保留；更新先读取任务以保留其他来源。每个笔记版本至多一条引用，摘录必须是对应版本正文的连续原文；多个要点可选择包含它们的原文段落。固定引用版本，后续笔记修改和归档不会改掉既有依据。任务详情显示摘录并可打开引用版本（只读），笔记显示关联任务。新结论需另行更新任务进展或项目背景，不自动改旧引用。

长期项目背景仍走已有脉络与正式文档流程；记录明确笔记ID、版本和摘录来源，必要时把笔记引用附到任务。原稿保留在固定历史版本中；润色只形成新的当前笔记版本。

## 验收

隔离数据覆盖：同日多篇/日期排序/空间与搜索、版本冲突、原请求重放、来源引用固定、归档恢复、只读与会话保护、HTTP来源和令牌检查、大段中文、备份及配套引擎恢复读取。前端覆盖保存中继续输入、失败重试、显式合并、安全阅读和归档恢复。实际浏览器验收结果在维护记录中保存；故障及样例均不进入真实工作数据。

“恢复原样”使用operation=restore、changes={}、expected_revision核对当前版本；恢复original_revision所指的最近一次整理前标题与正文，进入编辑并取消旧整理。保存与恢复均不改固定历史引用。原稿与整理版继续保留。恢复前网页确认当前正文将被替换。
