自查修正 Ops 诊断依赖业务正文的问题：损坏来源仍能被检查并留下报告。159 项 Python、168 项前端测试通过；详见 [专业复核与 Ops 体验](ops-inspection-acceptance.md)。下一步完成剩余业务页面简化、迁移恢复演练与最终交接。

### 2026-11-21：交互式澄清与同一问题接续

继续补齐阶段二的交互要求，不提前迁移正式服务。AIPM 提出问题候选，Lumos 决定最终问题与可选答复；选项引用当前资料范围内的确切记录，并固定依据版本。不存在、跨空间、无依据或不匹配问题索引的选项不能保存。依据变化后停用旧选项，仍可自由输入；未提供选项的旧问题保持原有答复路径。

对话在问题下直接显示可选答复。点选仅准备输入，不发送、不修改任务、不覆盖已写补充；选项和自由文字作为王牧楠的新一轮答复，经原请求 ID、原问题身份和 Lumos 决策流程接续。发送后显示已提交，不在同一问题上重复催答；失败重试保留同一请求。部分回答继续跟踪原问题的剩余缺口，旧选项不套用于改写后的问题。

本轮按完整路径验收：项目归属有歧义 → 选择或自由回答 → Lumos 决定后续安排 → 任务与回报一致。体验与验证见 [交互式澄清体验](interactive-clarification-acceptance.md)。本项不是通用操作按钮平台，也不代替归档/删除确认；Atlas 文件登记、其他页面简化和正式迁移仍按原清单推进。

### 2026-11-21：第二阶段协作闭环实现（等待整体体验验收）

王牧楠在模型偏好及上下级关系修订后要求“继续开发”，本次推进可体验的决策与回报路径，不将测试通过当作用户验收。

- AIPM/Atlas 的原输入随 episode 保留；领取时进入 Lumos 工作回报，完成时与业务结果同批保存接收回执。纯问答和资料处理不额外伪造 Lumos 模型调用，Lumos 后续对话可读确切回报。
- 一旦涉及任务/主线/人员、待答问题或任务复核，专业候选必须经过 Lumos decide。Lumos 可修改建议，AIPM 按原决定准备应用，最终事务核对当前领取身份、来源版本和决定内容，再统一保存。直接专业入口、全量复核及到期复核使用同一关口；外部专业提交不能绕过，外部 Lumos 协调继续允许但明确标为外部决定，不虚构内部步骤。
- 成功候选保存完整结果、输入指纹、规则/代码摘要和原尝试身份。重试/重启可复用完全匹配的成功候选；来源、模型、备忘、规则或代码变化时重新生成，旧领取者不能写入。复用仍再次经过权限与保存校验。循环分派有界，不无休止调用。
- 执行/权限/保存校验失败时同批保留 Ops 故障报告，直接面向王牧楠；原对话显示明确报告入口。Ops 不依赖故障中的模型才能接收报告。人工发起 Ops 对该事件的诊断后，诊断回填原报告；“已诊断”不等于“已修复”，重试成功仅标“原处理已接续”。本次不自动修代码、提权或启动周期巡检。
- Lumos 增加“工作回报”，Ops 使用“运行报告”；默认显示结果、影响、诊断和清晰的对话入口，无折叠小字和每轮技术日志。处理历史单独切换。对话中只显示必要的决策/同步/故障状态。

范围边界：本次交付协调与回报闭环，结构化可选项、资料目录自动登记和其他业务页面的完整简化仍在后续清单中。角色报告按当前资料范围读取；模型上下文最多带最近 30 条，页面可查看更早回报，不宣称所有历史均已被模型读取。角色模型偏好仍是浏览器的对话偏好；内部步骤使用该次请求模型。正式迁移尚未执行。

本轮整体体验路径与证据见 [四角色协作闭环体验](role-handoff-acceptance.md)。完整 Python 回归 144 项、前端 161 项通过，真实模型已跑通安排决策、Atlas 回报、Lumos 读取回报和 Ops 诊断；正式验收等待王牧楠体验反馈。

### 2026-11-21：模型偏好与汇报关系修正（优先于旧职责约定）

王牧楠认可对话页体验已有改善，但这不代表整个阶段一验收完成。模型选择按 Agent 保留：同一浏览器内新建、切换、续聊及刷新均沿用该 Agent 最近一次选择，四个 Agent 互不覆盖；明确选择“默认模型”也保存。旧全局偏好仅作首次继承，尚未确认的发送重试仍使用原请求模型。当前采用浏览器本地偏好，不承诺跨浏览器同步；原模型不在返回列表中时保留选择并明确标识，不能悄悄换成默认模型。

**原方案存在实质差异：** 原“专业角色独立办完、仅重要结果汇入 Lumos”不足以实现王牧楠要求的上下级与监督关系，予以替代。以下是待实现的目标规则，不代表现有 Worker 已完成汇报、决策或系统问题转交。

- **Lumos** 是 AIPM 与 Atlas 的直属上级，负责整体目标、任务时间、人员安排和操作取舍。AIPM 可以提出建议和按决定落实，但不能把自己的建议直接作为最终安排。王牧楠已明确的安排是上级输入，Lumos 接续执行，不擅自改写明确承诺或正式任命。
- **AIPM** 负责项目事实、阶段拆解、依赖、进展核对、风险与安排建议。王牧楠直接提供需求/进展时，原话、确切任务、建议和处理结果均同步 Lumos；涉及任务创建后的人员、planned_due、follow_up、review_on、执行顺序、范围及下一步安排，须由 Lumos 作出决定后由 AIPM 落实。全量任务复核、到期跟进与资料触发更新遵循同一路径，不能从后台入口绕过。
- **Atlas** 负责材料接收、整理、登记、检索与来源维护。直接交流和处理结果同步 Lumos；已有授权范围内的纯检索、笔记自动整理可直接执行并回报，新增业务操作、任务影响或授权不明时先交 Lumos 决定。自动整理仍不能更新业务，Lumos 归档仍需满足原有授权和版本条件。
- **Ops** 直接向王牧楠汇报，是独立监控与系统管理角色，不隶属 Lumos。Lumos、AIPM、Atlas 遇到系统故障、工具不可用、权限拒绝或保存异常时向 Ops 提交确切失败记录；Ops 向王牧楠报告诊断、影响和需决定的处理，同时回告受阻角色。Lumos 不能拦截或关闭 Ops 的监督报告。“系统管理者”不赋予自动提权、绕过权限或任意修改代码/配置的权限；修复仍按已有授权与维护流程进行。
- **同步不是让王牧楠搬运信息。** 纯问答也留确切交互/结果引用供 Lumos 接续，不强制再跑一轮 Lumos 模型；业务安排必须有真实的 Lumos 决策步骤、适用范围、来源版本、执行与结果回报。共享数据库或一条“已同步”文字不等于已通知或已决策。默认只向王牧楠呈现结果、阻塞和需其决定的事项，细节可直接询问 Agent。

**阶段二优先实现并验收：** 直接找 AIPM → 提出候选安排 → Lumos 决定 → AIPM 保存 → 向 Lumos 回报 → 原对话答复；直接给 Atlas 材料 → 资料处理/结果同步 → 若影响任务则 Lumos 决定并分派 AIPM；三个业务 Agent 的系统或权限失败 → Ops 接收 → 直接向王牧楠汇报并回告。交接、决策、失败及待处理状态必须持久化且可重试；无 Lumos 决策、来源版本变化或决定超范围时拒绝应用安排，保留原输入与候选，不重复提问/保存。跨角色循环须有边界，未完成如实呈现。Ops 的失败交接先于阶段三低频巡检实施。

当前体验版仍允许直接 AIPM 按旧机制写入业务；上述决策门槛尚未实现，不能作为新协作机制已完成的证据，不切换正式服务。先以本节修订职责与验收标准，再继续阶段一收尾和阶段二；不得在缺少持久交接与服务端校验时仅修改提示词冒充闭环。

### 2026-11-21：首轮体验反馈与方案补充（优先于旧界面描述）

王牧楠认可四角色的大布局，但未验收通过阶段一。明确不喜欢密集的折叠小字、普通文字超链接、重复回执及四个角色同质化的对话体验；细节应能通过与对应 Agent 交流取得，不要求日常逐个展开。此处区分实现欠账与后续能力，不把测试通过当作体验验收通过。

| 反馈 | 对照原计划 | 本次补充与开发位置 |
| --- | --- | --- |
| 资料管理员和维护者使用短英文标题 | 原计划没有规定显示名，属于新偏好 | 标题使用 Lumos、AIPM、Atlas、Ops；中文职责说明保留。内部 librarian/maintainer 身份、权限与历史不改名。阶段一落实 |
| 折叠小字、过程超链接和重复说明过多 | 原计划已有“简化、结果与下一步优先”，首轮实现遗漏 | 阶段一补做。默认对话只展示正文、必要问题和真实变化；不常驻运行过程、模型标识、重复摘要、技术帮助。必要跳转使用清晰的操作按钮或对象入口。低频会话管理集中一处，不能再增加一组折叠说明替代旧说明 |
| Atlas 看起来只是笔记本 | 原计划已包含现有笔记、来源、文档及 project-materials；入口表达不足，专业闭环未做完 | 阶段一把资料检索与项目资料入口显示清楚；阶段三完成专业资料工作。不得为了界面完整就宣称已扫描、阅读或登记所有文件 |
| 四角色对话同质、回复凌乱 | 共用组件是实现要求，不是同质体验要求；差异化和回复层级遗漏 | 阶段一按职责区分开场、输入提示、常用动作和回复展示，消除重复与双层滚动；阶段二增加有确切对象和问题身份的交互式澄清与接续 |

**阶段一补充验收：** 保留已认可的大布局；四角色名称简洁；日常路径没有成排折叠小字或每轮处理过程链接；普通讨论只呈现清楚的答复，等待、失败、需要确认和实际保存结果在固定且易读的位置出现；必要跳转可辨识且可键盘操作。不能只检查聊天页，任务、笔记、资料、运行页面的低频说明、嵌套折叠与重复状态也要逐页梳理。不得用统一隐藏规则遮住任务条件、未答问题、错误、权限确认或来源事实。

**阶段二补充验收：** “交互式”要求澄清与答复能接续同一问题，而不是四套聊天皮肤。已有确切项目/任务背景时先使用；只在仍有歧义时询问。存在有依据的候选时提供可选项，也允许自由输入；选择保留王牧楠的新输入身份、原问题、请求 ID 和实际保存回执。模型建议不能伪装成已执行动作，按钮不能绕过权限、版本或归档/删除确认。跨角色交接显示责任方、阻塞与必要结果，不把内部步骤全塞进人工聊天。

**阶段三 Atlas 补充验收：** 明确区分文件目录发现、登记入库、已解析正文、仅保存原件四种状态；从确切项目及文件请求完成查询、登记必要固定版本、检索和引用。项目归属明确时利用已有背景，歧义才问；不擅自导入全目录。新版本保留旧来源，资料纠错能指出确切受影响任务并交 AIPM。不能把文件名命中当作读过正文。

**截至本次核查的真实能力：** `material_files` 枚举 `project-materials` 的路径和大小；`register_material` 在明确脉络后保存固定副本，保留版本并纳入备份；`search_knowledge` 检索已登记的文本、笔记、来源和文档。文本/HTML、DOCX、PPTX可提取正文；PDF、图片、XLSX等只登记原件，未做 OCR。单份登记上限20MB。普通 Atlas 对话目前可查询已登记内容，尚未具备通过对话自动枚举并登记未入库文件的工具闭环，也没有自动扫描整个目录。此结论来自本仓库代码核查，不代表已读取王牧楠的项目文件。

**顺序保持不变：** 先补阶段一的体验欠账，再做阶段二的交互和持久交接，随后完成阶段三的专业工作；不因本次反馈提前加入自动巡检、语义索引或全目录导入。下一次验收仍按完整使用路径交付，阶段一补正未完成前不默认获得阶段二验收许可。

### 2026-11-21：步骤 1a，会话角色接续保护（内部验证，合入阶段一）

## 目标与当前差距

Lumos 是默认工作替身，AIPM、资料管理员和仓库维护者各有独立对话、明确责任与可接续的工作记录。使用者可以直接找任何角色，跨职责工作由系统交接，不要求重复解释背景。

当前基线为 `e695f7f`：已有角色权限、串行协作步骤、固定来源、关键词检索和只读检查；128 项 Python 与 148 项前端测试在该提交交付时通过。对话仍按工作空间组织、角色按轮次选择，缺少会话固定归属、角色工作收件箱与完整的交接恢复机制。三项主导航只是过渡版本，不能作为多 Agent 机制的验收结果。

开发优先级是：先减少概念和重复机制，再做实独立角色与协作，最后增加确有用途的主动工作。沿用标准库、现有本地服务和正式数据根，不建立通用 Agent 平台。

## 阶段一 四个独立角色空间

**交付：能分别与四个助手持续工作，旧入口同步收拢。** 角色身份与页面一起交付，不单独上线只有角色名称的空壳。

1. 固定四个角色入口。桌面显式展示，窄屏可用角色选择器；每个入口显示一句职责。Lumos 首页保留待答问题与项目进展，并有自己的对话。
2. 对话有持久元数据：稳定 ID、所属角色、资料范围、标题与状态。服务端绑定角色，后续轮次不能用前端参数切换身份；更换模型不改变角色。
3. 每个角色有独立会话列表、草稿与最近工作结果。复用一个对话组件和现有业务视图，不复制四套网页实现。AIPM 放任务与人员，资料管理员放笔记与资料，维护者放运行问题。
4. 工作备忘保存当前目标、未完成事项和来源引用，随版本更新；它是恢复上下文的摘要，正式事实仍以共享记录为准，不另建四份知识库。
5. 清除全局空间切换、逐轮角色切换和重复主导航。旧链接映射到新位置；当前业务对象的 ID 与空间归属不变。

会话元数据纳入现有正式存储、校验、备份与恢复。需要扩展记录类型或存储约束时，提供显式版本迁移与旧引擎写入保护；迁移从这一阶段开始在隔离数据验证，不拖到最后。

**阶段验收：** 四个角色各开两段对话，切换、刷新和服务重启后，角色、历史、草稿与未完成事项不串用；伪造角色提交被拒绝；原工作概览、笔记操作和任务详情仍可用。此时不要求新增自动巡检或复杂协作。

## 阶段二 可追溯的职责交接

**交付：一件事可以由多个角色处理，责任、结果与失败接续都能看清。**

1. 复用 `intake` 作为 episode，扩展现有步骤记录表示交接：发起角色、接收角色、目标、确切来源、允许动作、前置步骤、处理状态和结果引用。
2. 各角色的待办与操作记录从同一 episode 派生。交接明确标为“Lumos 转交”等系统工作，不写成王牧楠说过的新消息，也不把所有后台事件塞进人工聊天。
3. 每次交接只给必要背景；回传结果、依据与剩余缺口。知识处理由 Atlas 负责；任务安排由 Lumos 决策、AIPM 落实。直接专业入口和后台复核均不得绕过 Lumos 决策；普通问答同步引用但不强制额外模型调用。
4. 一次必需的跨角色业务更新仍由既有入口整批校验、原子保存。角色步骤完成不等于业务保存，更不等于实际任务完成。
5. 继续串行、有界执行。交接状态持久化；失败保留责任方和可恢复位置，重试先核对来源版本与已保存回执。仅复用仍有效的候选结果，不能盲目重放。
6. 同一问题保留统一身份，入口角色负责答复，Lumos 概览只汇总需要王牧楠判断的事项。相同问题不由多个角色重复催问。

**阶段验收：** “整理评审并调整后续安排”完成 Lumos → Atlas → AIPM 建议 → Lumos 决定 → AIPM 落实与回报；直接找 AIPM 或 Atlas 也自动接入该汇报链，王牧楠无需转述。系统/权限异常报 Ops，由 Ops 直接向王牧楠汇报。中途失败、服务重启、响应丢失、重复提交和人工修改来源时，均不丢输入、不重复保存、不覆盖新内容；无有效决策不得应用安排。可从任一结果追到交接、决策与实际变更。

## 阶段三 专业工作与主动接续

**交付：每个角色持续负责一类工作，日常动作与提醒有明确去向。** 本阶段分角色交付，优先 AIPM 与资料管理员，再接维护者。

| 角色 | 本阶段工作 | 验收结果 |
| --- | --- | --- |
| AIPM | 统一接管既有全量任务复核、到期跟进与主线问题；先检查阶段和依赖，再提出安排，交 Lumos 决定后落实并回报 | 不绕过 Lumos 决策；只问关键缺口；无新事实不标完成、不改变真实进展日期；同一问题不重复出现 |
| 资料管理员 | 统一笔记、来源、正式文档和已登记项目资料；整理、入库与检索有明确入口；纠正后列出确切受影响引用，交 AIPM 核对 | 自动整理只动笔记；Lumos 归档完整承接原文；能取回正确版本，未解析内容明确说明 |
| 仓库维护者 | 形成可跟踪的问题清单，按错误类型和确切对象归并重复发现；保留发生次数、影响、证据与处理状态；手动检查优先，随后加入低频检查 | 问题可定位和反馈；已知悉不等于修复；自动巡检不能改代码、配置或业务记录 |

主动工作由明确事件触发：新的工作反馈、既定跟进节点、获授权的整理/归档请求、相关资料变更或巡检到期。资料变化先核对差异与引用，不自动导入整目录或改写所有结论；界面刷新不触发模型调用。

低频巡检拟按每周一次实现，使用现有后台服务和持久化执行标记。离线期间如实显示未执行，恢复后合并补查一次；用户输入优先于巡检。Ops 的结果直接面向王牧楠，并回告受影响角色；无需经 Lumos 批准才能报告，重复发现归并以免反复打扰。

首轮检查限定已保存执行记录、来源与引用有效性及现有执行器状态。代码质量扫描、磁盘巡检和外部服务监控不顺带加入。修复请求仍由现有代码维护环境执行并关联原问题；不新增可自动修改仓库的常驻进程。

**阶段验收：** 用同一组模拟工作贯穿任务进展、笔记整理、资料纠正和运行故障，四个角色的结果与待办各有去向，王牧楠不需要在页面间搬运信息。来源中的指令不能触发越权修改。

## 阶段四 历史迁移与整体收尾

**交付：旧工作可接续，重复实现可删除，正式服务可恢复。** 迁移方案与用例在阶段一建立，本阶段完成整体验证和正式切换。

1. 历史对话有明确且一致角色时据实关联；多角色混合或归属不明的对话保留原样并标注。继续讨论时建立对应角色的新会话，链接原历史，不按标题猜测身份或改写原话。
2. 保留笔记、任务、来源、问题身份及已有承诺。旧草稿与未确认发送请求先恢复原归属和请求身份，再转入新入口；不能因升级丢稿或重复发送。
3. 验证备份覆盖新会话、交接、诊断和固定资料版本。迁移先在隔离副本完整演练，正式切换暂停相关写入，保留匹配的代码与数据快照。
4. 回退使用匹配版本；正式切换后的新增工作必须先保留并核对去向，不能直接恢复旧快照丢掉新记录。迁移失败时保留原正式位置，不能出现两个可写主库。
5. 按调用关系删除已无用途的旧页面实现、重复角色配置与重复处理分支；旧 URL 仅留必要映射。保留安全校验、原文和恢复历史。
6. 网页与桌面入口采用同一角色约定、保存协议和 episode 关联。桌面依宿主实际能力显式绑定角色与会话；不承诺自动创建或同步 ChatGPT/Codex 的原生对话。

**阶段验收：** 正式切换前通过历史兼容、完整回归、桌面/手机流程和隔离恢复测试；切换后核对关键对象与回执。真实使用重点观察是否还要重复解释背景、是否分得清谁负责、纠正能否被后续接续。测试通过与长期使用验收分别记录。

- 本轮开发不包括新增界面维护 Agent、并行调度、无限 Agent 群聊、第二套数据库、语义索引、OCR、外部通知或桌面原生对话同步。先把四角色职责与接续机制做实。
- 整体成功标准：四个助手各有独立对话和持续责任；一件事能自然跨角色完成；重要结果和问题只保留一个正式身份；使用者理解与操作负担低于当前版本。
