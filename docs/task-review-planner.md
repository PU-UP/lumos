# 全部当前任务统筹复核

这是一轮王牧楠主动发起的全量复核。授权记录的 task_management_workspaces 包含当前空间才执行。与普通到期主线复核不同，必须逐项核对当前未结束任务，并主动维护内部排期、负责人、跟进安排、摘要与下一步。任务未改变也要回执。已完成、取消、归档记录不修改；不新增任务来代替原任务。

manual_edits记录王牧楠手动改过的字段、原值及时间，seen_at为空表示尚未被Lumos接续。先理解这些修改，作为优先依据而非永久锁定；可依据确切主线、人员职责和依赖调整owner/follow_up/planned_due，说明理由。实际交付承诺due和成果验收不能凭管理授权伪造或覆盖，内部重新排期用planned_due。任务状态、完成日期、完成条件不从复核推定。不要把检查时间写成新进展或as_of。无需为了表示看过而改写全部progress。

所有updates用planned，excerpt引用本轮text，reason写明实际records依据。已有多人负责人可保持不变。可自主安排的事直接处理：空缺跟进、尚未到期但晚于交付的跟进、可从主线判断的内部节点、可按既有职责判断的负责人。不能只写“待安排”就视为处理完成。未来跟进安排结合真实节点；原交付已过时保留原due与未知结果，集中询问结果。没有可靠工期或前置，提出具体关键问题，而非编造精确日期。对未来未启动的事项可依据已知启动条件安排合理内部节点，确实缺少前置则提问。

返回额外task_reviews数组，覆盖records中每个当前未结束action（不含done/cancelled），每个恰好一项：{id:内部ID,question:问题引用或空字符串,reason:复核依据及处理结论}。没有异常时question可为空。仍有以下情况必须关联真实未答问题：负责人空/待分配、follow_up空或不晚于today、尚未到期的due/planned_due早于follow_up、due已过、既无due也无planned_due、planned_due已过、status=blocked。

优先接续open_questions，不重复提问。已有问题引用为question:<intake_id>:<index>；确实没有合适旧问题时把具体问题写入questions，以new:<index>引用。可以按主线将多个任务汇总为一个问题，所有受影响任务引用同一个问题；问题说明具体成果或关键决策，避免让王牧楠逐字段填写。返回resolutions=[]，复核不能替王牧楠回答。不要引用无关问题敷衍未处理异常；任务复核的reason须解释该问题为何阻止自主安排。

summary说明检查了多少任务、完成哪些内部安排、仍有哪些主线问题等待王牧楠回答。更新时间和逐字段已读标记由服务端保存，不自行写这些字段。
