# 本地任务与看板

2026-10-21。以原记录存储为唯一来源；页面不维护另一份任务库。仅使用 Python 标准库及原生 HTML/CSS/JavaScript，无安装依赖、外部字体或网络资产。

## 日常使用

2026-10-27 展示升级及后续反馈：默认紧凑列表，增加负责人列；五个状态按钮可多选，默认仅选待处理、进行中，点击可加入受阻、已完成、已取消，也可全部取消（空结果）。列表与看板共用空间、标签、负责人、状态、时间及搜索筛选；看板仍可拖动排序。

列标题可按任务、优先级、项目标签、负责人、状态、下次关心时间排序：连续点击切换正序、倒序、原顺序；优先级首次点击为高到低。日期首次点击为近到远，无日期始终在末尾；相同值保留原看板顺序。排序仅影响展示，不写入任务或修改看板顺序。负责人空值沿用 Mango。

时间窗口默认不限，可输入未来 N 天，0 为截至今天；以服务端上海日期为准，包含今天至第 N 天（含端点），并保留此前已到跟进日的事项。未填写 follow_up 的待处理任务仍显示，其他无日期状态在启用时间窗口时不显示；状态筛选仍生效。清空输入或点击“不限时间”恢复全部日期。项目标签仍使用 group，行内优先级、状态、follow_up 快捷保存不变，due 截止日期不受时间窗口影响。

行内每次仅保存改动字段，保留版本检查及请求重试标识。保存期间禁止重复写入；失败显示“重试上次修改”，版本冲突应刷新核对后重新修改。筛选（空间、项目标签、负责人、关键词、状态、未来天数）、排序及列表/看板选择自动保存到当前浏览器；刷新或重新打开同一地址恢复上次设置，首次使用才采用默认值。已不存在的分组或负责人恢复为全部。浏览器禁止存储时提示且保持当前页可用；损坏或无效偏好使用默认值。清除浏览器站点数据、更换浏览器或端口不会继承偏好。状态按钮不因零任务禁用，选中带勾号；无匹配任务明确显示已选状态。窄屏允许列表横向滚动，保证标题及编辑控件不挤压。

看板顶层分为“灵光”和“Lumos 仓库维护”，首次打开页面默认“灵光／全部分组”，之后恢复浏览器保存的选择。切换空间时清空分组、负责人及关键词筛选；点击刷新保留当前筛选。列表和看板使用相同筛选，两个空间的拖动排序互不影响。命令行 `tasks` 仍返回两个空间的全部当前任务，避免对话侧遗漏维护事项。

每个任务有一个可选分组：在详情编辑中选择已有名称或直接输入新名称，留空为“未分组”。分组不需要预先建立，随当前空间任务自动汇总；没有任务使用的分组不显示。同名分组在两个空间内独立筛选。Agent 可根据工作内容整理，也可按用户说明调整；已有背景脉络及来源历史保留在“关联背景”中。初始灵光分组为雷达验证、感知与地图、数据闭环、软件架构。这是 Agent 根据当前任务作出的整理，可以继续修改。

`py -3 lumos.py serve` 后访问 http://127.0.0.1:8765 。端口冲突时用 `--port`。仅允许本机访问，不用于局域网／公网部署。服务运行期间，页面可新增或修改任务、标记完成／取消、查看详情、历史及所属脉络文档。

卡片可直接拖动：跨列切换状态，列内上下排序，落点以卡片上方横线提示；拖到列底部则追加。状态与顺序在同一批次保存，刷新后保留。聚焦卡片后 Alt + 上下键调整顺序，Alt + 左右键切换列。已取消任务在已完成列内移动时保留取消状态。筛选时按可见落点插入完整列表，隐藏任务之间的相对顺序保留；列底部指完整列底部。命令行 tasks 的近期关注仍按提醒规则排序，不受手动排序影响。保存失败保留原显示并提示核对；网络失败可重复同一拖动重试，版本冲突需刷新后核对。

对话侧运行 `tasks` 查看所有当前任务；`task <ID>` 查看完整详情。当前任务只来自 active/waiting 脉络，不包含 archived/retained。通用 `context` 仍可读取历史归档。近期关注包含逾期、今天至七天后到期、已到跟进日、受阻和重要事项；已完成／取消不提醒。默认日期为上海日期，`tasks --today YYYY-MM-DD` 可指定查询基准。页面不限时间时保留所选状态的无日期任务；启用时间窗口时仅保留无日期待处理任务。

页面打开和点击“刷新”时读取最新记录，没有后台推送或自动轮询。对话中修改后刷新页面即可看到。当前数据尚无业务任务时展示空看板，不填充模拟任务。

更新后端代码后须重启正在运行的看板服务，再刷新页面。关闭浏览器或再次双击启动器会复用旧服务，不会重新加载 Python 模块；新页面配旧后端可能报 `Unknown request field`。交付时须核对实际使用端口的服务，不能只验收新启动的测试服务。

已记录任务默认以只读详情打开：直接展示标题、状态、已设置的日期、下一步与进展，背景、完成条件和来源历史可按需展开。点击“编辑”才启用表单；“取消编辑”放弃本次输入并返回原详情。新增任务直接进入表单。下一步和完成条件支持多行显示，长内容不再挤在单行输入框内。

详情顶部可直接点击状态按钮（待处理、进行中、受阻、已完成、已取消），无需进入编辑。点击即保存，成功后返回看板并更新所在列；只提交状态字段，沿用版本冲突保护与幂等重试。当前状态不可重复点击，只读时禁用切换。标记完成仍只记录用户报告，不推定技术验收通过。

负责人未指定或留空时默认为 Mango；已有明确负责人在更新其他字段时保持原值。看板可按负责人筛选，与工作脉络、关键词共同生效，也同步筛选近期关注。优先级为低（蓝）、中（橙）、高（红），默认中，同时显示文字标签。原有 normal／普通对应中，high／重要对应高；高优先级继续触发近期关注。读取旧任务时补默认展示值，不改写旧历史。

## 共用任务保存

详情优先展示当前结论与进展、下一步；相关资料、来源、修改历史分别折叠。资料按标题逐份展开，区分直接关联与所属脉络背景，历史脉络及已替代记录有标注。Markdown 标题和列表仅作安全文字排版，不执行 HTML。历史按字段显示改前／改后及来源、原因，不再重复未改内容。

讨论保存必须同步核对受影响任务：用 `task-save` 更新 progress/next_step 和确切 context，用原批次维护文档及直接依据链接，再读回 `task`/`context`。仅修改背景文档不会自动改写任务，也不会推定任务完成。提醒日期放在 follow_up，下一步描述动作，避免日期双份维护。详情 API 保留 documents 文本映射，新增 document_info 提供标题、关联类型及脉络状态；不递归展开同脉络的其他讨论。

先读取 `tasks` 的 `seq`，在数据根 `incoming/` 写 UTF-8 请求，再运行 `task-save <路径>`。以下仅为格式，不能导入真实历史：

```json
{
  "request_id": "0123456789abcdef0123456789abcdef",
  "expected_seq": 4,
  "source": {"type": "user", "ref": "可独立理解的用户原话及日期"},
  "changes": {"context": "work-current", "text": "用户实际提出的任务"}
}
```

每次新操作生成 UUID 的32位十六进制 request_id。更新加上已有 `id`，`changes` 仅填变化字段。相同请求重试沿用 request_id；已保存请求不会产生第二个任务，复用同一 ID 改内容会拒绝。`expected_seq` 为全库版本，其他任务或文档更新也可能触发冲突；先核对新记录再生成新请求，不自动覆盖。

移动已有任务时，`changes` 只传 `status`，额外传顶层 `before_id`（目标列某任务 ID，或 null 表示列末）。内部 `board_order` 由服务端统一生成，不能作为普通 changes 输入；未排序任务按 ID 稳定排列在已排序任务后。读接口 `board_order` 返回看板顺序，`tasks` 与 `attention` 保留关注排序。无需数据库迁移，顺序随任务记录参与历史、备份及恢复。

支持字段：text、context、status、condition、details、next_step、progress、due、follow_up、priority、owner。日期用 YYYY-MM-DD 或空字符串清除；priority 为 low/normal/high（低/中/高），默认 normal；owner 为负责人姓名，最多300字符，省略或空白默认 Mango。更新时省略 owner 保留已有负责人。状态为 todo/doing/blocked/done/cancelled。新建至少有标题和所属脉络，其余可后补。无完成条件时使用“用户确认完成：标题”，不虚构技术验收。完成由用户报告记录，重开会撤下当前完成声明，旧结果保留在历史中。

另支持 `group`：单行字符串，最多80字符，去除首尾空白；空字符串清除分组，更新时省略保留已有值。分组与其他任务字段共用历史、冲突保护、幂等重试和备份。空间由所属 context 的可选 `workspace` 决定，只允许 `lingguang` 或 `lumos`，通过文档批次维护；旧脉络默认灵光，唯一兼容例外为 `lumos-maintenance` 默认维护。`tasks` 返回的 contexts 补齐 workspace，旧记录无需迁移。页面编辑空间会选择该空间的背景脉络，具体背景可在“关联背景”展开选择；只改分组不改 context。

页面来源由服务端标记为用户保存；对话侧必须提供用户来源，Agent 建议不能当作承诺任务。最初来源和最近修改来源分别保留；正文和进展每次保存都有历史。

任务保存与原批次保存共用验证及提交逻辑，在一次进程锁内完成，无需手工编辑任务工作副本。不会修改文档，因此不需要 `--quiet-files`；这不改变文档批次、备份和迁移暂停外部文件编辑的要求。存在候选会话时拒绝任务写入；中断留下会话时用原有 status/recover 流程核对恢复。

## 数据与访问边界

SQLite 与文档版本一起构成完整工作记忆；继续用 `backup` 整组备份。备份也包含新模块和网页资产。不要只复制数据库，也不要直接移动正式数据根。

服务只绑定 127.0.0.1，校验 Host、写入 Origin 和随机页面令牌，限制请求大小，只提供固定静态资源；任务内容按文字显示。没有多用户身份系统，不能将端口转发到外网。数据库整体版本冲突采用保守拒绝，不做自动合并。
