# 本地任务与看板

2026-10-21。以原记录存储为唯一来源；页面不维护另一份任务库。仅使用 Python 标准库及原生 HTML/CSS/JavaScript，无安装依赖、外部字体或网络资产。

## 日常使用

`py -3 lumos.py serve` 后访问 http://127.0.0.1:8765 。端口冲突时用 `--port`。仅允许本机访问，不用于局域网／公网部署。服务运行期间，页面可新增或修改任务、标记完成／取消、查看详情、历史及所属脉络文档。修改状态在详情里完成，第一版无拖拽。

对话侧运行 `tasks` 查看所有当前任务；`task <ID>` 查看完整详情。当前任务只来自 active/waiting 脉络，不包含 archived/retained。通用 `context` 仍可读取历史归档。近期关注包含逾期、今天至七天后到期、已到跟进日、受阻和重要事项；已完成／取消不提醒。默认日期为上海日期，`tasks --today YYYY-MM-DD` 可指定查询基准。无日期任务留在看板中。

页面打开和点击“刷新”时读取最新记录，没有后台推送或自动轮询。对话中修改后刷新页面即可看到。当前数据尚无业务任务时展示空看板，不填充模拟任务。

已记录任务默认以只读详情打开：直接展示标题、状态、已设置的日期、下一步与进展，背景、完成条件和来源历史可按需展开。点击“编辑”才启用表单；“取消编辑”放弃本次输入并返回原详情。新增任务直接进入表单。下一步和完成条件支持多行显示，长内容不再挤在单行输入框内。

## 共用任务保存

先读取 `tasks` 的 `seq`，在数据根 `incoming/` 写 UTF-8 请求，再运行 `task-save <路径>`。以下仅为格式，不能导入真实历史：

```json
{
  "request_id": "0123456789abcdef0123456789abcdef",
  "expected_seq": 4,
  "source": {"type": "user", "ref": "可独立理解的用户原话及日期"},
  "changes": {"context": "work-current", "text": "用户实际提出的任务"}
}
```

每次新操作生成 UUID 的32位十六进制 request_id。更新加上已有 `id`，`changes` 仅填变化字段。相同请求重试沿用 request_id；已保存请求不会产生第二个任务，复用同一 ID 改内容会拒绝。`expected_seq` 为全库版本，其他任务或文档更新也可能触发冲突；先核对新记录再生成新请求，不自动覆盖。

支持字段：text、context、status、condition、details、next_step、progress、due、follow_up、priority。日期用 YYYY-MM-DD 或空字符串清除；priority 为 normal/high；状态为 todo/doing/blocked/done/cancelled。新建至少有标题和所属脉络，其余可后补。无完成条件时使用“用户确认完成：标题”，不虚构技术验收。完成由用户报告记录，重开会撤下当前完成声明，旧结果保留在历史中。

页面来源由服务端标记为用户保存；对话侧必须提供用户来源，Agent 建议不能当作承诺任务。最初来源和最近修改来源分别保留；正文和进展每次保存都有历史。

任务保存与原批次保存共用验证及提交逻辑，在一次进程锁内完成，无需手工编辑任务工作副本。不会修改文档，因此不需要 `--quiet-files`；这不改变文档批次、备份和迁移暂停外部文件编辑的要求。存在候选会话时拒绝任务写入；中断留下会话时用原有 status/recover 流程核对恢复。

## 数据与访问边界

SQLite 与文档版本一起构成完整工作记忆；继续用 `backup` 整组备份。备份也包含新模块和网页资产。不要只复制数据库，也不要直接移动正式数据根。

服务只绑定 127.0.0.1，校验 Host、写入 Origin 和随机页面令牌，限制请求大小，只提供固定静态资源；任务内容按文字显示。没有多用户身份系统，不能将端口转发到外网。数据库整体版本冲突采用保守拒绝，不做自动合并。
